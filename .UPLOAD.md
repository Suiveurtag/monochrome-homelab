# Publier et déployer Monochrome

Ce dépôt est publié sur `https://github.com/Suiveurtag/monochrome-homelab` (branche `main`). En production, Docker Compose construit et lance trois conteneurs : le frontend Monochrome, PocketBase et l'importeur Spotiflac. Le frontend écoute sur le port `3000` de l'hôte ; le reverse proxy doit publier ce port sur `https://monochrome.brighter-builds.com`.

## 1. Vérifier puis pousser les changements sur GitHub

Depuis le poste de développement, à la racine du projet :

```bash
git status
bun install
bun run lint
bun run build
```

Examiner les fichiers avant de les ajouter. Ne jamais commiter `.env`, `pb_data/`, mots de passe, sauvegardes ou autres secrets ; ils sont locaux au serveur.

```bash
git diff
git add <fichier1> <fichier2>
git diff --cached
git commit -m "type: description courte"
git pull --rebase origin main
git push origin main
```

Exemples de types de commit : `feat`, `fix`, `docs`, `refactor` ou `chore`. Si le rebase produit un conflit, le résoudre, ajouter les fichiers corrigés avec `git add`, puis exécuter `git rebase --continue` avant le `git push`.

## 2. Premier déploiement sur le serveur

Pré-requis : Docker Engine avec le plugin Compose, Git, un enregistrement DNS `A`/`AAAA` de `monochrome.brighter-builds.com` vers le serveur, et un reverse proxy HTTPS (Caddy, Nginx Proxy Manager, Traefik, etc.).

```bash
ssh <utilisateur>@<serveur>
sudo mkdir -p /opt/monochrome
sudo chown "$USER":"$USER" /opt/monochrome
git clone https://github.com/Suiveurtag/monochrome-homelab.git /opt/monochrome
cd /opt/monochrome
docker compose config
docker compose up -d --build
docker compose ps
docker compose logs --tail=100
curl -I http://127.0.0.1:3000
```

Les données PocketBase sont conservées dans `/opt/monochrome/pb_data`. Ce dossier ne doit jamais être supprimé pendant une mise à jour.

Configurer ensuite le reverse proxy avec :

- domaine public : `monochrome.brighter-builds.com` ;
- destination : `http://127.0.0.1:3000` ;
- certificat TLS/Let's Encrypt activé ;
- support WebSocket et envoi des en-têtes `Host`, `X-Real-IP`, `X-Forwarded-For` et `X-Forwarded-Proto`.

Exemple minimal avec Caddy :

```caddyfile
monochrome.brighter-builds.com {
    reverse_proxy 127.0.0.1:3000
}
```

Le port `3000` n'a pas besoin d'être ouvert publiquement si le reverse proxy tourne sur le même serveur. Les ports `8090` de PocketBase et `8787` de l'importeur ne sont pas publiés par le fichier Compose racine.

## 3. Mettre la production à jour après un push

Après chaque `git push`, se connecter au serveur et exécuter :

```bash
ssh <utilisateur>@<serveur>
cd /opt/monochrome
git status --short
git pull --ff-only origin main
docker compose up -d --build --remove-orphans
docker compose ps
docker compose logs --tail=100 monochrome
curl -fsS -o /dev/null https://monochrome.brighter-builds.com && echo "Déploiement OK"
```

`git status --short` doit être vide avant le pull. S'il ne l'est pas, ne pas écraser les changements présents sur le serveur : les examiner et les sauvegarder d'abord.

## 4. Contrôle et retour arrière

Contrôles utiles :

```bash
docker compose ps
docker compose logs -f monochrome
docker compose logs -f pocketbase
docker compose logs -f selfhost-importer
```

Pour revenir au commit précédent tout en gardant les données PocketBase :

```bash
cd /opt/monochrome
git log --oneline -10
git checkout <commit_stable>
docker compose up -d --build --remove-orphans
```

Après diagnostic, revenir sur la version courante avec :

```bash
git checkout main
git pull --ff-only origin main
docker compose up -d --build --remove-orphans
```

Ne pas utiliser `docker compose down -v` et ne pas supprimer `pb_data/` : cela entraînerait une perte de données.
